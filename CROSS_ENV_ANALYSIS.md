# Cross-Environment Discovery Analysis

The `jfps discover` command now includes built-in cross-environment analysis via the `--cross-env-analyze` flag. This eliminates the need for a separate tool and keeps all discovery functionality unified.

## Quick Start

```bash
# Generate discovery outputs from multiple environments
jfps discover --all --url https://prod.jfrog.io --token $PROD_TOKEN
jfps discover --all --url https://staging.jfrog.io --token $STAGING_TOKEN

# Analyze across environments and report duplicates
jfps discover --cross-env-analyze

# View the reports
cat output/cross-env-analysis.txt          # Text summary
open output/cross-env-analysis.html        # Interactive report
cat output/cross-env-analysis.json         # Structured data
```

## How It Works

The `--cross-env-analyze` flag:
1. **Discovers** all environment directories in `--output` (default: `./output`)
2. **Reads** the `report.csv` from each environment (generated by `--repos` or `--all`)
3. **Identifies** repositories that exist in multiple environments
4. **Generates** three complementary reports (text, JSON, HTML)

## Flags

### `--cross-env-analyze`
Enables cross-environment analysis mode. No network calls are made.

### `--output` (default: `output`)
Path to the directory containing environment subdirectories. Each subdirectory should contain discovery outputs from a single environment.

Example structure:
```
output/
├── production/
│   ├── report.csv
│   ├── instance.json
│   └── audit.html
├── staging/
│   ├── report.csv
│   ├── instance.json
│   └── audit.html
└── development/
    ├── report.csv
    ├── instance.json
    └── audit.html
```

### `--cross-env-report` (default: `<output>/cross-env-analysis.txt`)
Base output path. All three formats (`.txt`, `.json`, `.html`) are automatically generated.

## Output Files

Three complementary formats are **automatically generated** with the same base name:

### 🌐 Interactive HTML Report (`.html`) — **Recommended**
Visual exploration with:
- Beautiful, responsive design with gradient header
- Summary stat cards (environments, repos, duplicates)
- Environment breakdown in grid layout
- Expandable duplicate repository cards
- Detailed side-by-side configuration comparison
- Click to expand/collapse duplicates
- Mobile-friendly and works offline
- Full styling and interactivity embedded

### 📄 Text Report (`.txt`)
Quick summaries with:
- Summary statistics across all environments
- Per-environment breakdown (repo counts, duplicates)
- Detailed duplicate repository analysis
- Configuration comparison
- Easy to parse and grep in scripts

### 📊 JSON Report (`.json`)
Structured data with:
- Complete environment metrics
- All duplicate repository details
- Suitable for API integration
- Programmatic analysis and alerting
- Dashboard visualization

## Examples

### Basic cross-environment analysis
```bash
jfps discover --cross-env-analyze
```

Generates:
- `output/cross-env-analysis.txt`
- `output/cross-env-analysis.json`
- `output/cross-env-analysis.html`

### Custom output paths
```bash
jfps discover --cross-env-analyze \
  --output ./discoveries \
  --cross-env-report ./reports/analysis.txt
```

Generates:
- `./reports/analysis.txt`
- `./reports/analysis.json`
- `./reports/analysis.html`

### Full workflow: discover multiple environments + analyze
```bash
# Production
jfps discover --all \
  --url https://prod.jfrog.io \
  --token $PROD_TOKEN

# Staging  
jfps discover --all \
  --url https://staging.jfrog.io \
  --token $STAGING_TOKEN

# Development
jfps discover --all \
  --url https://dev.jfrog.io \
  --token $DEV_TOKEN

# Analyze across all three environments
jfps discover --cross-env-analyze

# Explore the interactive report
open output/cross-env-analysis.html
```

## Understanding the Reports

### HTML Report Features

The HTML report provides an interactive experience:

1. **Summary Cards** - Key metrics at a glance
   - Number of environments analyzed
   - Total unique repositories
   - Count of repositories in multiple environments

2. **Environment Grid** - Per-environment breakdown
   - Shows total repos and duplicates per environment
   - Hover effects for better UX
   - Organized in responsive grid

3. **Duplicate Repository Cards** - Detailed duplicate analysis
   - **Click to expand** - See full configuration details
   - **Side-by-side comparison** - Compare same repo across environments
   - **Color-coded** - Yellow background warns of duplicates
   - **Badge count** - Shows how many environments have the repo

4. **Expandable Details** - Full repository metadata
   - Package type and repo type
   - Project assignment
   - File count and storage usage
   - Creation date and creator
   - Last activity date
   - Cleanup policies (if any)

## Use Cases

### Configuration Audits
Identify repositories with:
- Same name but different package types
- Policy mismatches across environments
- Storage size discrepancies
- Project assignment variations

### Compliance & Governance
Find duplicate repos that might indicate:
- Naming convention violations
- Inconsistent cleanup policies
- Unauthorized replication
- Data residency issues

### Migration Planning
Use duplicate information to:
- Validate federation setup
- Plan repository consolidation
- Confirm backup/disaster recovery configuration
- Identify obsolete duplicates to be cleaned up

### Environment Validation
Verify that:
- Production repos are properly replicated to staging
- Backup environments have expected coverage
- Development mirrors match production structure

## Integration Examples

### Parse JSON with `jq`
```bash
# Count total duplicates
jq '.summary.duplicate_count' output/cross-env-analysis.json

# List all duplicate repo names
jq '.duplicates[].name' output/cross-env-analysis.json

# Find repos in specific environments
jq '.duplicates[] | select(.environments[] == "production")' output/cross-env-analysis.json

# Get duplicate count per environment
jq '.environments[] | {name, duplicate_count}' output/cross-env-analysis.json
```

### Automated Alerting
```bash
DUPLICATE_COUNT=$(jq '.summary.duplicate_count' output/cross-env-analysis.json)
if [ "$DUPLICATE_COUNT" -gt 100 ]; then
  echo "Warning: Found $DUPLICATE_COUNT duplicate repositories"
  # Send alert, create ticket, etc.
fi
```

### CI/CD Integration
```bash
# Generate analysis and fail if duplicates found
jfps discover --cross-env-analyze || exit 1
DUPLICATES=$(jq '.summary.duplicate_count' output/cross-env-analysis.json)
if [ "$DUPLICATES" -gt 0 ]; then
  echo "ERROR: Found $DUPLICATES duplicate repositories"
  exit 1
fi
```

### Dashboard Export
```bash
# Generate report and pipe to visualization tool
jfps discover --cross-env-analyze && \
  cat output/cross-env-analysis.json | my-dashboard-import-tool
```

## Troubleshooting

### No duplicates found
This is normal if:
- Each environment has unique repository names
- This is the first discovery run (only one environment)
- Repositories are properly segregated by environment

### Missing environments
The tool only includes directories with a `report.csv` file. Ensure:
- Discovery was run with `--repos` or `--all` flag
- Output files are in the expected location
- Directory structure matches `output/<environment>/report.csv`

### Custom paths not working
Always use `--cross-env-report` for the full path:
```bash
# Wrong - only changes txt file
jfps discover --cross-env-analyze --cross-env-report my-report

# Correct - generates my-report.txt/.json/.html
jfps discover --cross-env-analyze --cross-env-report ./reports/my-report.txt
```
